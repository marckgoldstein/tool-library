# Working on the Tool Library

Source of truth for requirements: PRD v1.0 (see README). Decisions are numbered D1–D36; stories S1–S24.
Don't change a signed-off rule silently: propose it, and log it as the next D-number.

## Commands
- `npm run dev` · `npm run build` · `npm run lint` · `npm run typecheck`
- `npm test` (Vitest, real Postgres test DB) · `npm run test:e2e` (Playwright, builds and starts on :3100)
- `npm run db:generate` after editing `src/db/schema.ts`, then `npm run db:migrate`; `npm run db:seed` for local data

## Architecture rules
- Next.js 16 App Router (TypeScript). Read the version-matched docs in `node_modules/next/dist/docs/` before using a Next API you aren't sure of: `proxy.ts` replaced middleware; `params`/`searchParams`/`cookies()` are async.
- Drizzle ORM on PostgreSQL (D36). Migrations are SQL files in `drizzle/`, generated by drizzle-kit and committed.
- Every loan status change goes through `src/server/loans/service.ts` (S22): one transaction, item row locked, loan_event written, emails after commit. Never update `loan.status` anywhere else.
- Overdue is derived (`isOverdue`), never stored (D30). Times are stored in UTC and shown in the viewer's timezone (R7).
- No background jobs in v0.1 (D29).
- Contact details are only ever returned to the member they were sent to (D13). Never put contact details or addresses in emails or logs.
- Every query is scoped to the member's group; admin pages check `role === "admin"`.

## Frontend rules
- **Browser support policy (D33):** Baseline Widely available features need no fallback. Anything newer must follow the fallback advice in its Modern Web Guidance guide. Prefer platform features (`<dialog>`, popover, `:user-invalid`, native form validation) over JavaScript libraries.
- Before building UI, consult the Modern Web Guidance guide for the pattern (`modern-web-guidance` skill) and the Impeccable playbooks (`impeccable` skill); PRODUCT.md holds the product context they read. This is an **Operate** surface: precision and familiar patterns over expression.
- Forms: real `<form>`, `<label>`, correct `type` and `autocomplete`, errors named with the recovery.
- Copy: plain, specific, kind. Controls name their action.
- **Copy Review sheet** (https://claude.ai/artifact/2k3RHWnWYxBp85cG8ENGvL, sheet "Copy"): one row per piece of user-facing copy, with a Source column of `file:line`. Whenever you add, change or remove user-facing copy (pages, dialogs, errors, emails, canned messages, notices), update the matching row's "Current copy" (and Source) in the same piece of work; add rows for new copy and delete rows for removed copy. Never write in "Recommended copy": that column is the reviewers'. To apply a recommendation, change the code, then copy the new wording into "Current copy".
